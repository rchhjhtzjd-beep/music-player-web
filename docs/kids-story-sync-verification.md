# 儿童故事字幕与时长修复验证

验证日期：2026-11-19。基线提交：`d430496f1cc9f4f9d662a1d42459edf16dedb310`。

## 已确认的根因

1. 原 `server.js` 把 RSS `enclosure.length` 文件字节数放进 `duration`，前端再除以 1000 当作毫秒。例如 The Stolen Bicycle 的 `9950442` 被错误显示为 `165:50`。
2. 原字幕入口拼接未经验证的 `/transcripts/<title>.txt`，没有时间戳也没有翻译，却标记为“双语字幕”。
3. 故事播放仅替换 `audio.src`，没有清除旧歌词、旧音乐身份或旧请求。旧音乐的时间轴会作用于故事面板；播放结束会进入旧音乐队列。
4. 首次直接播放故事时 `currentIndex` 仍是 -1，播放按钮无法暂停。异步返回的旧歌曲 URL 和歌词也可能覆盖刚选中的故事。

## 修复后的行为

- 三个后端入口（Express、Vercel、Netlify）共享故事解析。只从 `itunes:duration` 读取时长，支持秒、MM:SS、HH:MM:SS；字节数使用独立字段。
- RSS 时长在音频载入前标为“约”。音频的 `loadedmetadata` / `durationchange` 到达后，列表和播放栏使用同一实际时长。未知或非有限值不会产生错误分钟数或 NaN 进度。
- 缓存保留原 60 条的身份、顺序和简介。2026-11-19 的实际 RSS 可按音频 URL 核实其中 51 条；另 9 条时长保留 null，等待音频 metadata。
- 每次切换媒体都会清除歌词时间轴、重置显示，并使旧播放/歌词请求失效。故事有自己的队列，暂停、恢复、上下条、随机、循环与自然结束不会串入旧音乐。
- 有合法时间戳时，字幕仅由 `audio.currentTime` 驱动；句首之前、句间空白和句尾之后不误高亮。查看其他故事的字幕不会跟随正在播放的音频高亮。
- 没有时间戳时明确显示“暂无同步字幕”及来源。原文使用普通文本样式，不猜字幕地址，不按字数均分时间。
- 可选人工核对字幕按精确音频 URL 关联；显式提供的 `subtitleDurationSeconds` 与实际录音相差超过 0.5 秒时停止同步。这个检测不能证明对白内容已对齐，也不能识别所有等长内容替换。

## 验证边界

- 检查的实际 [Storynory RSS](https://www.storynory.com/feeds/stories/) 包含 60 条音频，没有提供带时间轴的字幕。此次修复消除了错误时长、错误同步及状态串线，并验证了可选字幕播放机制；没有制作或声称完成 60 条故事的逐句双语对齐。
- 浏览器验证为 Chrome，未在用户的 Mac Safari 上实测。
- 本次验证针对仓库源代码和实际本地预览，外部托管平台的线上部署状态不在已验证结果内。
